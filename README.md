## Сайт

- Адаптивна головна сторінка для міжнародного перевізника.
- Напрямки: Молдова (аеропорт Кишинів), Бельгія, Нідерланди, Польща, Австрія, Чехія, Швейцарія, Данія та Німеччина.

**У цій версії заявки із сайту надходять через WhatsApp. Автоматичне передавання заявок із сайту до CRM ще не активоване.** Серверний endpoint для майбутньої інтеграції збережений у `api/bookings.js`.

## CRM (`/crm/`)

Робочі розділи:

- Огляд — ключові показники, останні звернення та швидкі дії.
- Бронювання — створення й редагування заявок, статуси, призначення рейсу, оплати, примітки та експорт CSV.
- Фінанси — журнал платежів, методи оплати, дати, суми та залишки.
- Рейси — дата й час відправлення, маршрут, транспорт, водій та кількість вільних місць.
- Маршрути — країни, міста, тарифи, валюти, тривалість та активність.
- Клієнти — контакти та історія поїздок.
- Транспорт — моделі, типи, реєстраційні дані, місткість і статус.
- Водії — контактні дані, документи та статус.

Початкові записи показують логіку роботи інтерфейсу. Їх можна створювати, редагувати та видаляти у локальному тестовому просторі. Це приклади для перегляду, не фактичні дані перевізника.

## Як відкрити локально

1. Розпакуйте архів у звичайну папку.
2. Запустіть `OPEN-PREVIEW-WINDOWS.bat`, щоб відкрити сайт і CRM у браузері. Або відкрийте `index.html` та `crm/index.html` окремо.
3. У CRM введіть `test` у поле логіна та `test` у поле пароля.

Форма сайту працює через WhatsApp навіть при локальному відкритті файлу. Для WhatsApp потрібне підключення до інтернету та встановлений або вебклієнт WhatsApp.

## Підключення спільної бази даних

Для спільної роботи сайту й CRM з різних пристроїв можна підключити Supabase та розгорнути проєкт на Vercel.

### 1. Створення бази

1. Створіть проєкт у Supabase.
2. Відкрийте **SQL Editor → New query**.
3. Виконайте файл `supabase/schema.sql` повністю.
4. У **Project Settings → API** скопіюйте Project URL, anon/publishable key і service-role/secret key.

### 2. Змінні Vercel

Додайте у **Vercel → Project → Settings → Environment Variables**:

| Змінна | Призначення |
|---|---|
| `SUPABASE_URL` | URL проєкту Supabase |
| `SUPABASE_ANON_KEY` | Публічний ключ для клієнта CRM |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверний ключ для API; не розкривати у браузері |
| `TELEGRAM_BOT_TOKEN` | Необов’язково: токен Telegram-бота |
| `TELEGRAM_CHAT_ID` | Необов’язково: чат для сповіщень |

Після додавання змінних виконайте новий deployment.

### 3. Створення адміністратора

1. У Supabase відкрийте **Authentication → Users → Add user**.
2. Створіть користувача з робочим email і паролем.
3. Скопіюйте User UID.
4. У SQL Editor виконайте запит, замінивши UID та ім’я:

```sql
insert into public.profiles (id, full_name, role, active)
values ('ВСТАВТЕ-USER-UID', 'Ім’я адміністратора', 'admin', true)
on conflict (id) do update
set full_name = excluded.full_name, role = 'admin', active = true;
```

Для менеджерів створіть окремі облікові записи та профілі з роллю `manager`.

### 4. Синхронізація маршрутів

Після налаштування Supabase публічний сайт може отримувати активні маршрути через `/api/routes`. CRM використовує спільні таблиці бази даних для бронювань, клієнтів, маршрутів, рейсів, транспорту, водіїв і платежів.

Форма сайту в цій версії навмисно залишена на WhatsApp. Для автоматичного створення бронювань у CRM потрібно окремо активувати надсилання форми на `/api/bookings` та перевірити інтеграцію на тестових записах.

## Технології

- Frontend: HTML, CSS, JavaScript.
- Backend: Vercel Serverless Functions.
- Database/Auth: Supabase (PostgreSQL, Supabase Auth, Row Level Security).
- Сповіщення: Telegram Bot API (необов’язково).

## Дані, які ще потрібно внести від перевізника

- Точні міста відправлення та прибуття для кожного напрямку.
- Дні та час відправлення.
- Вартість поїздок і валюти.
- Правила передоплати, оплати, повернення та скасування.
- Норми багажу та умови перевезення дітей.
- Дані фактичного автопарку та водіїв.
- Контакт для отримання заявок і бажані канали сповіщень.

Секретний ключ Supabase зберігайте лише у серверних змінних середовища. Не додавайте його до HTML, JavaScript браузера або відкритого GitHub-репозиторію.
